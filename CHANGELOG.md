# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/),
and this project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed
- Dead-letter handling is now bounded and consistently routed (audit OPS-001). `DeadLetterRef` previously retained every dead-lettered message forever (an unbounded memory leak) while some failure paths bypassed it entirely — `LocalActorRef` silently dropped fire-and-forget messages to a closed mailbox. The sink now keeps a **monotonic total** (`DeadLetterRef::total()`, surfaced by the `nexus.actor_system.dead_letters` gauge, which previously reported the retained-sample count and could undercount) and dispatches a PSR-14 `MessageDeadLettered` event per message, while retaining only a **bounded ring buffer** of the most recent messages (`captured()`, default 1000) so memory stays stable under a flood. `LocalActorRef::tell()` and `enqueueEnvelope()` now route a dropped delivery (closed or full mailbox) to dead letters instead of dropping it silently; `offer()` still returns the outcome to the caller without dead-lettering (so broker-redelivery paths are not double-handled). **Upgrade note:** `captured()` is now a recent-sample window, not a complete history — use `total()` or subscribe to `MessageDeadLettered` for exhaustive accounting; previously-silent closed-mailbox drops now appear in dead letters.
- The Messenger consumer's responder-side pending-ask map is now bounded (audit REL-008). `ReceiverActor` previously stored one pending entry per un-answered ask for up to `askPendingTimeout` (30 s) with no cap, so a producer flooding ask envelopes with distinct correlation IDs could exhaust consumer memory. `ReceiverActorConfig` gains `maxPendingAsks` (default 1024): once the map is full a new ask is shed — rejected for broker redelivery instead of tracked — and `nexus.messenger.asks.shed` is incremented, so shedding is deterministic load shedding rather than message loss (the broker redelivers when a slot frees). The live pending count is now actually emitted as the `nexus.messenger.asks.pending` gauge (previously documented but never wired), and on stop/restart every still-pending ask is rejected for redelivery so none is silently abandoned.
- Persistent `Effect::unhandled()` / `DurableEffect::unhandled()` now route the command to the actor system's dead letters instead of silently keeping the state unchanged (audit DSL-001), matching `Behavior::unhandled()` in the stateless model and the documented behavior. A new `ActorContext::toDeadLetters()` backs it. Protocol drift (an unsupported command) is now observable rather than swallowed.
- Added regression guards that the persistence command handler is invoked as `($state, $ctx, $command)` in both the event-sourced and durable-state engines (audit DSL-004); the documentation examples already reflect this order, and the guards prevent future drift.

### Security
- Messenger producer → target routing can now be authorized per envelope (audit SEC-012). `StampMessageRouter` selects the target actor from a producer-controlled `TargetActorPathStamp`, so any producer with publish rights could invoke every registered target and consume its capacity. It now accepts an optional `TargetAuthorizer`: a resolved target is only returned if the authorizer permits the envelope's producer to reach it, and a denied envelope is unroutable (rejected or dead-lettered per the `ReceiverActor` policy) so an unauthorized producer never reaches the target actor. `MapTargetAuthorizer` is a fail-closed static allowlist mapping a producer identity — carried in the new `ProducerIdentityStamp` (wire header `X-Nexus-Producer-Identity`, round-tripped by `NexusMessengerSerializer`) — to the exact target paths it may reach; a missing/unknown identity or a target outside the list is denied and logged. The change is backward compatible (the authorizer defaults to `null`, preserving the previous any-producer-any-target behavior). **Trust boundary:** a producer-set identity stamp proves origin only as far as the producer is trusted; across mutually untrusted producers the identity must be established at a trusted boundary (authenticated transport, broker ACL, or signed envelope), which the docs now call out.
- The `nexus-wallet-app` example is now hardened against being deployed as-is (audit SEC-013). Its `/admin/wallets` endpoint — which exposes every wallet's balances via raw SQL — previously required no authentication at all; it now demands the `admin` role (`AdminAllLedgersHandler` is annotated `#[RequiresRole('admin')]` and the route carries `AuthorizationMiddleware`, so anonymous or user-only callers are rejected 401/403 and compilation fails closed if the enforcer is removed, per SEC-003). Admin tokens are minted from a **separate** `WALLET_ADMIN_TOKENS` list so an admin capability can never be issued by accident from the user `WALLET_AUTH_TOKENS` list. The demo also fails closed at boot: with `WALLET_ENV=production`, `WalletConfig::assertProductionSafe()` throws `DemoDefaultsInProductionException` if the Postgres password, user tokens, or admin tokens still hold a built-in demo value, and the Postgres port in `compose.yaml` is bound to `127.0.0.1` so the database is not reachable off-host.
- WebSocket channel actors are now bounded against resource exhaustion (audit SEC-002). A channel actor is spawned per distinct URL key, so churning unique keys previously grew actors, refs, and mailboxes without limit. `ChannelActorRegistry` now enforces a cardinality cap (default 10 000, tunable via `WsApplication::withMaxChannels()`): past the cap a new channel connection is refused with a `1013` close (`ChannelCapacityExceededException`) instead of spawning, and dead channels free their slot. Channel actors default to a bounded mailbox (1 024, `DropNewest`), and `WebSocketChannelActor::stopWhenEmpty()` lets a channel passivate on last close. Pair with the SEC-001 upgrade authentication and the SEC-010 Origin allow-list to keep the channel population bounded and authorized.
- Added `OriginAllowlistMiddleware` to defend against cross-site WebSocket hijacking and CSRF (audit SEC-010). The WebSocket open path did not validate `Origin`, and cookie bearer tokens are attached by the browser to cross-site upgrades and requests automatically. The new PSR-15 middleware rejects (403) any request whose `Origin` is not in an exact allow-list (scheme + host + port, no wildcards or suffix matching); it runs as WebSocket `wsMiddleware()` in the pre-upgrade handshake (rejecting before the 101) and on state-changing HTTP routes. WebSocket upgrades (GET) are checked by default; missing `Origin` is configurable via `allowMissingOrigin`. `CookieTokenExtractor` documents the required `HttpOnly`/`Secure`/`SameSite` cookie attributes and the Origin/CSRF pairing.
- Health endpoints now separate opaque public liveness from detailed internal readiness (audit SEC-011). The single `HealthCheckHandler` returned per-check states plus the raw exception class and message on a route the docs mounted publicly at `/health`, disclosing internal topology and component/error detail. A new `LivenessHandler` returns only `{"status":"up"|"down"}` (200/503) with no check names or details — safe to expose. `HealthCheckHandler` (now positioned as an internal/authenticated `readyz` route) redacts the raw exception class and message by default; pass `includeErrorDetail: true` to surface them on a trusted internal route. **Upgrade note:** mount `LivenessHandler` on your public probe and move `HealthCheckHandler` behind auth/an internal route; a thrown check no longer leaks its exception message unless you opt in.
- The Swoole HTTP servers now enforce a native request-size cap by default (audit SEC-009). `SwooleWorkerConfig`/`SwooleThreadConfig` gain `maxRequestBodyBytes` (default 8 MiB), wired to Swoole's `package_max_length`, so oversized requests are rejected at the protocol parser — before PHP materializes the body via `rawContent()` — for every HTTP method and for both known-length and chunked bodies. Previously an oversized or unknown-length body could exhaust request memory before any framework limit ran (the application-level `BodySizeLimitMiddleware` skipped GET bodies and unknown lengths). Tune it with `->maxRequestBodyBytes()`. **Upgrade note:** requests larger than 8 MiB are now rejected by default; raise the cap for services that accept larger uploads.
- Cluster topology is now secure by default (audit SEC-007). `ClusterTopology::create()` rejects a non-loopback bind (anything other than `127.0.0.0/8`, `::1`, `localhost`) without TLS, which previously accepted cluster control and actor traffic from any reachable host in the clear; a new `allowInsecureBind: true` argument is the explicit development override. A new `ClusterTopology::createProduction()` factory requires both TLS and an auth secret, so a production topology can never expose plaintext or admit an unauthenticated peer. `Host::isLoopback()` was added to `nexus-core`. **Upgrade note:** nodes binding to `0.0.0.0`/a routable address must now pass a `TlsConfig` (ideally via `createProduction()`) or set `allowInsecureBind: true` for a trusted, fenced dev segment.
- `JwtAuthenticator` now enforces issuer, audience, and subject constraints (audit SEC-006). It previously validated only the signature and time, ignoring issuer/audience entirely — so with a shared signing key, a correctly signed token minted for another issuer, service, or tenant was accepted (cross-service replay). New constructor arguments `issuers` (any-of), `audience`, `subject`, and `leeway` (clock-skew tolerance) are enforced, and any constraints configured on the lcobucci `Configuration` (`setValidationConstraints()`) are now merged in and honored too. **Upgrade note:** deployments sharing a signing key across services/tenants should set `issuers` and `audience`; existing single-issuer setups are unaffected (defaults enforce signature + time as before).
- Pooled database connections are now sanitized before reuse (audit SEC-005). `ConnectionPool::release()` rolls back any active transaction unconditionally and runs an optional dialect-specific `PoolConfig::$resetQuery` (e.g. `DISCARD ALL`/`RESET ALL`) to clear per-session state (roles, `search_path`, `SET` variables, temp tables, advisory locks) before returning a connection to the idle channel; a connection whose cleanup fails is poisoned rather than requeued with dirty state. `EntityManagerPool::release()` likewise rolls back the EM's underlying connection (and already clears the identity map on reuse via `clearOnReturn`). Previously a later request — including a different tenant — could inherit an open transaction, role, search path, locks, or tenant state from a prior borrow. Multi-tenant deployments should give each tenant its own named pool or set `resetQuery`.
- `PhpNativeSerializer` no longer defaults to unrestricted `unserialize()` (audit SEC-004, CWE-502). The constructor now requires an explicit `allowedClasses` allow-list, enforced at **every depth** of the object graph — a disallowed class nested inside an allowed top-level type is refused and the whole payload is rejected (previously only the top-level type was checked, so gadget objects could ride in as nested properties). Allow-any deserialization is an explicit, self-documenting opt-in via `PhpNativeSerializer::forTrustedData()` for data the application produced itself. The DBAL and Doctrine event/snapshot/durable-state stores no longer default their `MessageSerializer` to `PhpNativeSerializer` — a serializer is now a required constructor argument, so recovery can no longer silently cross an unsafe native-deserialization boundary. `TypeRegistry::allClasses()` returns the registered classes as a starting allow-list. **Upgrade note:** persistence-store constructions and `new PhpNativeSerializer()` calls must now pass a serializer/allow-list explicitly (or `forTrustedData()`); no wire format changed, so existing rows still deserialize.

### Fixed
- Annotated HTTP authorization now fails closed at compile time (audit SEC-003). A route whose handler class declares `#[RequiresAuth]`/`#[RequiresScope]`/`#[RequiresRole]`/`#[RequiresAnyScope]`/`#[RequiresAnyRole]`/`#[Authorize]` but has no route-level authorization middleware previously served HTTP 200 unprotected; `compile()` now throws `UnprotectedRouteException`. Registering `AuthorizationMiddleware` globally (where it runs before routing) throws `GlobalAuthorizationMiddlewareException` at compile instead of failing per request at runtime. The check is marker-driven via new `Monadial\Nexus\Http\Security\AuthorizationRequirement`/`AuthorizationEnforcer` interfaces (implement the enforcer marker on custom authorization middleware); WebSocket routes are verified against their `wsMiddleware()`/per-route pipeline the same way. Upgrade note: applications that relied on annotated-but-unenforced routes serving traffic will now fail at startup — add the missing middleware or remove the attribute.
- Cancelling a repeating Swoole timer now works after the first fire (audit REL-005). `scheduleRepeatedly()` returned a handle bound to the initial `Timer::after` ID; once the first invocation fired, the recurring `Timer::tick` had a different ID and `cancel()` cleared a dead timer, leaving the tick running forever (stopped/restarted actors retained ticks). The handle is now retargeted to the live timer at the after→tick handover, and `DeferredCancellable` (timers scheduled before `run()`) delegates cancellation to the materialised timer instead of only flagging itself.
- WebSocket connections are now authorized BEFORE the 101 upgrade (audit SEC-001). A new pre-upgrade `HandshakeGate` runs the WebSocket middleware pipeline — the same `AuthenticationMiddleware`/`AuthorizationMiddleware` used on HTTP routes — against the upgrade request; missing/invalid/expired/under-scoped credentials are rejected with plain HTTP 401/403 on the not-yet-upgraded connection, and unmatched paths with 404. New DSL: `WsApplication::wsMiddleware()` (global WS middleware) and per-route middleware on `ws()`/`channel()`; `paramResolver()` now also feeds the WebSocket `HandlerInstantiator`, so `#[FromPrincipal]` resolves the same principal that authorized the handshake. The Swoole servers switched from the post-upgrade `Open` event to a custom RFC 6455 `handshake` handler that performs the accept and dispatches open with the authorized request. Previously, WebSocket routes documented with auth were reachable without any auth pipeline.
- `Props::fromFactory()`, `Props::fromStatefulFactory()`, and `Props::fromContainer()` now enforce their handler contracts with an explicit `InvalidPropsFactoryException` (wrapped in `ActorInitializationException` at spawn) instead of `assert()` (audit DSL-008). Production deployments running `zend.assertions=-1` previously deferred wrong factory results into obscure downstream failures such as `Call to undefined method stdClass::initialState()`; they now fail at actor start with the factory and actual type named.
- `#[FromActor]` parameters are now type-checked at HTTP compile time (audit DSL-009): a parameter whose declared type cannot hold an `ActorRef` (scalar, incompatible class, union without `ActorRef`) is rejected with `InvalidFromActorParameterException` when the handler is compiled, instead of compiling successfully and failing with a `TypeError` on first invocation. `ActorRef`, nullable, union-with-`ActorRef`, `object`, `mixed`, and untyped parameters remain valid.
- Swoole mailbox admission is now truthful (audit REL-001): every `Channel::push()` result is inspected, so a failed push can no longer be reported as `Accepted` and silently lost. "Unbounded" mailboxes expose their real 65,536-slot physical capacity via `SwooleMailbox::$effectiveCapacity`, report `isFull()` honestly, and throw `MailboxOverflowException` at the physical cap; `DropOldest` reports `Dropped` when the swap fails instead of claiming acceptance. `LocalActorRef::ask()` now fails the returned future immediately with the new `AskUndeliverableException` when the mailbox drops or backpressures the ask message, instead of making the caller wait out the full ask timeout.
- Persistence side-effect hooks (`thenRun()`/`thenReply()`) now execute on every effect instead of being silently dropped off the persist path (audit DDD-001). On `Effect::persist(...)`/`DurableEffect::persist(...)` they keep running after the durable write with the new state; on `none()`, `unhandled()`, `reply()`, `stash()`, and `stop()` they now run after the effect's primary action with the unchanged current state, making `Effect::none()->thenReply(...)` the canonical read-only query. Code that relied on hooks being dropped on non-persist effects must remove those hooks.
- HTTP route handlers given as a `'#name'` actor shorthand string now fail at compile time with `ActorShorthandHandlerException` and an actionable message pointing to the supported `#[FromActor('name')]` injection, instead of a cryptic reflection error (audit DSL-002). The shorthand was never implemented; `HttpApp` docblocks now show the real actor-backed route pattern.
- `HttpApp::compile()` is now terminal and idempotent (audit DSL-003, DSL-006): the first call freezes the DSL and spawns worker-local/pool-singleton actors exactly once; repeated calls reuse the frozen state and live actor table instead of respawning actors and throwing `ActorNameExistsException`. Registering routes, actors, middleware, or configuration after compilation now throws `HttpAppAlreadyCompiledException` instead of being silently ignored.

## [0.1.0] - 2026-07-21

### Added
- Initial actor system with Fiber and Swoole runtimes
- Supervision trees with one-for-one and all-for-one strategies
- Persistence and event sourcing with in-memory, DBAL, and Doctrine backends
- Multi-process clustering via Swoole
- Psalm plugin for generic actor type inference
- Symfony Messenger bridge (`nexus-messenger`): MessengerActorRef/MessengerGateway producers, supervised ReceiverActor with backpressure-aware ack, pluggable MessageRouter, Nexus-backed Messenger serializer, and LifecycleWatchdog worker recycling
- Symfony Console runners (`nexus-messenger-console`): `nexus:messenger:consume` and `nexus:messenger:produce` commands with limit/memory/time watchdog wiring
- Threaded Swoole console adapter (`nexus-messenger-console-swoole`): `nexus:messenger:consume-threads` command using the Swoole worker pool; each thread owns an independent transport connection and actor system; limits are per-thread
- Broker request/reply (`nexus-messenger`): `MessengerActorRef::ask()` enabled via `AskSupport` (wired with `MessengerBridge::askSupport()`); `TransportReplyChannelFactory` with Ephemeral/DeleteOnShutdown/Persistent lifecycle; `MapReplySenderLocator` for SSRF-safe reply routing; `ReceiverActor` process-ack path with configurable `askPendingTimeout`; interop via `X-Nexus-Correlation-Id` / `X-Nexus-Reply-To` headers
- Project quickstart: `composer create-project nexus-actors/skeleton` with the interactive `nexus:setup` wizard (runtime, modules, application architecture preset)
- Code generators (`nexus-actors/maker`): `make:actor` (handler, functional, stateful, event-sourced, durable-state types) and `make:message`, built on nette/php-generator
- All 41 packages split to read-only repositories and published on Packagist

### Changed
- Internal cross-package constraints moved from `dev-main` to `^0.1`
