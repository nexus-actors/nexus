# Remote Ask + Message Context Design

Date: 2026-02-26
Status: Approved
Scope: nexus-core, nexus-runtime, nexus-cluster, nexus-cluster-swoole

## Goals

- Implement remote `ask()` end-to-end with reply correlation, cancellation propagation, and dedup safety.
- Make envelope context first-class and mandatory: `requestId`, `correlationId`, `causationId`.
- Make `Future` cancellable via API (`Future::cancel()`), with runtime-level cancellation semantics.
- Keep actor-level API ergonomics: actor code still uses `ctx->reply()`.

## Non-Goals (This Phase)

- No backward compatibility guarantees (explicitly accepted).
- No new remote-specific exception hierarchy in this phase.
- No hard delivery guarantees (best-effort transport, idempotent protocol handling).

## Confirmed Decisions

- Use typed, first-class envelope fields (not metadata-only).
- Future cancellation is caller-driven (`Future::cancel()`), not timeout-only.
- Reuse existing timeout/future exception model; add `FutureCancelledException`.
- Cancellation propagation is best-effort (no strict cancel ack round-trip requirement for local terminal state).
- Envelope IDs are mandatory everywhere, including local `tell()`.

## Architecture

### 1) `nexus-core`: Envelope Context

Update `Envelope` to make context mandatory and typed:

- `requestId` (mandatory)
- `correlationId` (mandatory)
- `causationId` (mandatory)

Planned API shape:

- `Envelope::of(object $message, ActorPath $sender, ActorPath $target): self`
  - Auto-generates all three IDs.
- Immutable modifiers:
  - `withRequestId(...)`
  - `withCorrelationId(...)`
  - `withCausationId(...)`
- Keep `metadata` for free-form extension.

ID generation defaults:

- `requestId`: new unique ID
- `correlationId`: defaults to requestId
- `causationId`: defaults to requestId

### 2) `nexus-runtime`: Cancellable Futures

Extend async primitives:

- `Future::cancel(): void`
- `FutureSlot::cancel(): void`
- `FutureSlot::onCancel(Closure): void` (callback registration for propagation hooks)
- New exception: `FutureCancelledException implements FutureException`

Semantics:

- `resolve/fail/cancel` are idempotent terminal operations; first wins.
- `await()` throws `FutureCancelledException` after cancellation.
- Runtime implementations (`fiber`, `step`, `swoole`, tests) must implement consistent behavior.

### 3) `nexus-cluster`: Remote Ask Protocol + Registries

Introduce internal control message objects carried over existing transport/serializer channel:

- `RemoteAskRequest`
- `RemoteAskReply`
- `RemoteAskCancel`
- `RemoteAskCancelled`
- `RemoteAskAck` (for retry/dedup coordination)

`RemoteActorRef::ask()` flow:

- Create cancellable slot and timeout timer.
- Generate request envelope/context IDs.
- Register pending request (`requestId -> pending slot`) on client side.
- Send `RemoteAskRequest`.
- `Future::cancel()` triggers `RemoteAskCancel` best-effort.

`ClusterNode` flow:

- On `RemoteAskRequest`:
  - Dedup check by requestId.
  - Build local envelope preserving IDs.
  - Inject transport-backed `senderRef` so `ctx->reply()` emits `RemoteAskReply`.
  - Track active request state.
- On `RemoteAskCancel`:
  - Best-effort cancellation of active request state.
  - Emit `RemoteAskCancelled`.
- On `RemoteAskReply`:
  - Resolve pending slot by requestId.
- On `RemoteAskCancelled`:
  - Fail/cancel pending slot with `FutureCancelledException`.

Cleanup + race handling:

- Clear pending/active registries on terminal state.
- Ignore late duplicates and late terminal messages safely.
- Optional short TTL caches for dedup terminal outcomes.

### 4) `nexus-cluster-swoole`

- Reuse existing transport wiring.
- Ensure control messages work through current serializer/IPC path.
- Add integration coverage for remote ask + cancellation across workers.

## Data Flow

### Tell

- Every `tell()` builds envelope with mandatory IDs (auto-generated by factory).
- IDs are serialized/deserialized locally and remotely unchanged.

### Local Ask

- `requestId` identifies ask operation.
- `correlationId` links chain; defaults to requestId.
- `causationId` indicates causal parent; defaults to requestId unless overridden.

### Remote Ask

- Request uses requestId for matching.
- Target worker injects transport-backed senderRef.
- Actor replies via `ctx->reply()` without protocol knowledge.

### Cancel

- Caller invokes `future.cancel()`.
- Client sends best-effort cancel control frame.
- Server transitions state and emits cancelled signal.
- First terminal result wins at caller slot.

## Error Handling

- Timeout: existing `AskTimeoutException`.
- Cancellation: new `FutureCancelledException`.
- Malformed/unknown control messages: ignore + warning log (non-fatal).

## Testing Strategy

### Core

- Envelope IDs mandatory/non-empty.
- Factory autogeneration + immutable overrides.
- IDs present for local tell/ask envelope creation.

### Runtime

- `Future::cancel()` behavior and `await()` exception.
- Idempotence and race cases: cancel vs timeout vs resolve.
- Runtime-specific slot behavior parity (`fiber`, `step`, `swoole`).

### Cluster

- `RemoteActorRef::ask()` success path.
- RequestId correlation to replies.
- Cancellation propagation and local cancellation terminal behavior.
- Dedup behavior for duplicate request/reply/cancel.
- Late reply after timeout/cancel ignored.

### Cluster Swoole

- Cross-worker integration for ask/reply/cancel.

## Risks and Mitigations

- High churn from mandatory envelope fields: mitigate with centralized factory/helpers and broad test updates.
- Serializer format changes: mitigate with synchronized serializer + tests (compact serializer versioning if needed).
- Race complexity in ask lifecycle: mitigate with strict single-assignment slot semantics + deterministic tests.

## Success Criteria

- Remote ask works in unit/integration paths.
- `Future::cancel()` available and enforced across runtimes.
- Envelope IDs present in all message paths.
- Full test/lint suite passes after refactor.
